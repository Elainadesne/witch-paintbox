# 魔女画匣

每次生图，都是魔女看板娘施展的一次绘图魔法。

独立的 SillyTavern 前端扩展，提供可拖动悬浮球、五个主板块、从上向下展开的金字塔系谱图，以及使用偏好的保存。

点击缇娅（或悬浮球）打开竖向菜单：**AI生图、指定插图、设置**。按住拖动仍可调整位置，不再区分长按与短按。选择“指定插图”可读取最新回复，按原文行号选择配图位置。图层加载期间、加载失败，或浏览器缺少 `PointerEvent`、`ResizeObserver`、`createImageBitmap`、`matchMedia` 时，仍显示原来的“绘”悬浮球。

也可从酒馆的扩展设置栏展开“魔女画匣”，点击“打开魔女画匣”进入同一设置界面；悬浮球隐藏时仍可使用此入口。

独立四方前端通过 `Sifang` 原生接口读取楼层、保存配图标记并在标记原位置显示画框。需宿主同时提供 `native-text-write` 与 `native-image-markers` 能力；设置、预设 AI 和定位锚点流程沿用原有逻辑。写回时校验存档、分卷、楼层版本和原文，保存成功后才确认完成。图片生成仅更新对应画框；队列、图片历史、图库、回顾和清理由画匣管理，宿主只保留临时显示状态。

标题右侧的铃铛在打开画匣时，通过酒馆的扩展版本接口检查当前安装分支是否有 Git 更新；有更新时显示红点，悬停可查看分支与本机提交，点击可重新检查。自动检查间隔至少 15 分钟，失败后至少 1 分钟；网络失败或非 Git 安装显示无法检查。更新操作仍在酒馆扩展管理中进行，铃铛不会自动拉取代码或切换分支。

生图 API 支持 NovelAI 与 GPT（OpenAI 兼容）两套独立配置，模型 API 支持酒馆聊天补全连接或自定义接口。界面采用暖白页眉、较低亮度的暖纸色正文底、茶褐文字和金茶色强调；配置页使用下划线与留白分区，两类 API 在窗口右上角切换。

手机设置窗口会在系统安全区内留出额外间距，通常使用约 90% 的可用高度，正文在窗口内滚动；窄屏的 API 切换独立成行，顶部按钮保持至少 44px 点击区域。键盘或浏览器工具栏改变可见区域时，窗口跟随调整并保留输入与草稿。短视口优先使用留白内的剩余高度，双指缩放保留浏览器原有行为。安全区和键盘信息取自当前宿主窗口；宿主未提供安全区时保留基础边距，不修改整个酒馆的 viewport 设置。

看板娘缇娅取代原来的“绘”悬浮球，身边带一只胡桃木画匣；电脑上站在页面底部，手机上站在酒馆输入栏上沿。外观、日常互动、生图与报错表现、台词及退路说明见下节“桌宠缇娅”。

## 桌宠缇娅

缇娅是画匣的看板娘，取代原来的“绘”悬浮球。电脑上站在页面底部，手机上站在酒馆输入栏的上沿，身边是一只胡桃木画匣。点击她打开竖向菜单（**AI生图、指定插图、设置**），按住拖动可移动位置。

- **外观与资源**：使用一张全身立绘加分层部件（帽子、帽尖、呆毛、两条发辫、手臂、杯子、五种表情），由扩展内置的 WebGL2 小渲染器驱动呼吸、眨眼和弹簧摆动，不使用 Live2D 或第三方库。画匣同样为分层贴图（箱体、内外盖、抽屉、支架、颜料格）。资源位于 `pet/` 目录（24 个文件，含 webp 图层、画匣骨架 `box_rig.json`、样式 `pet.css`，约 790 KB），代码位于 `src/pet/`（14 个模块）。
- **日常互动**：鼠标靠近时她会看向指针。一段时间无操作会抱着画匣缩进屏幕右边缘打盹（电脑约 15 秒，手机约 3 秒），指针靠近时探出头；被放在别处时，安静一阵后原地打瞌睡（电脑约 35 秒，手机约 23 秒），指针靠近或点击即醒。拖到屏幕左右边缘松手会躲进边缘，从边缘拉出在半空松手会掉到地上。电脑上用鼠标在她帽子上来回蹭、手机上按住帽子不放可摸头，她会眯起眼睛、头往手那边歪；摸满约 3 秒会害羞并往旁边跳开一步（缩在边缘里或工作中时不会跳开）。手机上键盘弹出时，她躲到输入栏后面。宽屏和窄屏分别记住她站在地面还是躲在边缘、靠哪一边及所在高度。
- **处理与生图**：打开菜单时画匣打开。“处理”时她顺着回复阅读，表情专注；找到插入点后说出对应台词，台词下附插件自己的结果文字（例如“已保存 3 处配图标记……”）。生图时画匣支成画架，她把帽檐右侧翻起并用画笔别住，画纸上一层层晕染；图片返回后在画纸上显影，颜料格换成该图颜色，随后图片从画架飞进对应楼层的画框（画框不在视野内时飞向聊天区边缘淡出）。排队中的图在画架后错开摆成空白画纸；配置页和角色图的试绘完成后收回画匣里。单张图等待满 60 秒未返回时，她在画架前打瞌睡、鼻子吹泡泡、帽檐滑下，图到或报错时醒来。
- **出错表现**：按插件标注的错误类别表演，表演后说台词，台词下附插件报错原文。找不到 `@` 的角色或服装时，画匣盖子里升起一块没刻字的铜字块；密钥不对时，钥匙插在锁里拧不动；额度不够时，颜料格见底并扬起细灰；断网时，送颜料的金线断开；超时（插件等满五分钟）时，早已在画架前睡着的她因泡泡破掉而惊醒；其它错误时，画匣冒出一团烟。找不到角色说“名册”台词；密钥、额度、断网、限流、超时和未知错误说“魔力回路”台词；格式、解码、存储、设置类错误不说台词，只显示报错原文。
- **独立四方前端**：在独立四方前端的原生配图路线（Sifang）里，她与在酒馆里一样跟随处理和生图，排队、作画、完成、出错、取消均有对应表现。宿主提供可选的 `ui.imageMarkerRect`（能力 `native-image-marker-rect`）时，画好的图从画架飞入宿主画在原位的画框；飞行期间画框里的新图先隐藏，落定后显示；宿主不提供该接口时，画好的图收回画匣，不飞向楼层。宽屏上，酒馆输入栏沿页面底部横到她默认的角落时（独立四方前端的窗口视口下故事栏位于该处），她和画匣站到输入栏旁边，不压住发送按钮；输入栏两侧均无空位时，她仍站在角落。输入栏移动时，未自定位置的她会重新站到合适的地方。
- **偏好与退路**：使用偏好的“桌宠缇娅”分组提供大小滑杆和两项开关。**缇娅的大小**可在 50%～150% 之间调整，拖动即时生效并自动保存，点击“恢复默认”回到 100%；人物、画匣和点击区域同步缩放，菜单与台词文字保持原大小。**缇娅的台词**默认开启，仅在操作或有结果时触发，同一句 3 分钟内不重复，关闭后不再说话但出错仍显示报错文字；**缇娅的动作**默认开启，关闭后仅保留呼吸和眨眼，取消走动、摆动及图片飞入楼层的动画（系统开启“减少动态效果”时同样生效）。旧版本已收纳的缇娅仍可点击画匣唤出。大小比例、上述开关、关闭状态和位置随使用偏好保存，并纳入完整配置导出。浏览器缺少 `PointerEvent`、`ResizeObserver`、`createImageBitmap` 或 `matchMedia` 时，或图层加载期间及加载失败时，使用原“绘”悬浮球；浏览器无 WebGL2 时，显示静止立绘和合上的画匣，无动画。

触发台词一览（同一句冷却 3 分钟）：

- **打开菜单**：画匣已经支好了。今天要给哪一段故事配画？
- **被拿起拖动**：唔……换个角落摆画架吗？这里光线确实更顺手一点。
- **处理中**：别催别催，我正顺着字里行间找适合落笔的位置呢……
- **找到插入点**：找到了，这几幕光影正好，画框已经给你嵌进楼层里啦。
- **排队**：前面还有正在调色的画布，这张草稿我先按顺序压在镇纸下面啦。
- **取消排队中的图**：唔，这张先不画了吗？那我把空白画纸收回匣子里咯。
- **开始画**：外貌铜牌核对无误，画师底色铺好……凝！
- **NAI 多角色分栏**：左边留给第一位，右边留给第二位，分栏结界已经隔开了，绝不会把发色染串的。
- **画完**：干透啦，快看看显影效果！要是觉得光影差一点，点右边的按钮我再给你重画一版。
- **找不到角色**：等一下，画匣名册里还没有登记这位角色或衣服的标签呢，先去锚定页补上档案我才能下笔呀。
- **接口出错**：呜，远方的魔力回路好像断开了，颜料送不过来……稍微检查一下接口密钥吧？

## 重前端配图（测试分支）

支持穿透同源 iframe 挂载画框，优先识别 `#readingContent` 与 `#game-text-display` 叙事容器；等待已识别的前端完成初始化，跳过隐藏或不可访问的 iframe。正文局部重绘或克隆替换后复用原画框与生图任务，不刷新整楼 HTML。全屏查看器提升到酒馆顶层窗口；离开楼层或 iframe 导航后清理旧文档监听。

原文含完整 `<now_plot>` 或 `<gametxt>` 时，插入点只建立在这些叙事块内部，末尾在闭合标签之前。脚本、注释与代码中的同名标签不算叙事块；普通楼层继续按原有行间位置插入，不为跳出气泡而跨过尚未读完的正文。

单楼层回合缓存适配使用提案中的 `GameManagerInstance` / `AppStorage` 接口。处理前固定前端实例、当前缓存与原文；回看历史、后台结算或回合不匹配时停止写入。前端历史保存失败或超时会明确提示酒馆与前端的同步状态，不自动重试。历史图片按回合正文（排除配图标记）区分；相同正文无法唯一识别的回合仅保留本次页面图片，避免串图。其他前端的私有缓存结构不自动推测，需要实机确认其接口。

## 生图回顾与使用偏好

- **自动清理生图**：默认关闭，可选择保留最近 1、3、7 天。按生成时间清理所有角色卡在当前设备保存的图片历史；开启或更改期限后立即检查，之后每小时、页面恢复可见和下次启动时检查。角色锚定图独立保存，不参与清理。清理成功后释放当前页面的对应图片缓存；支持 BroadcastChannel 的同源页面也会同步移除。
- **自动生图**：默认关闭，开启后固定仅处理最新一楼，无单独的范围开关。仅响应本次打开聊天后新增的完整图片标记；等酒馆完成回复、正文稳定 1 秒，再按楼层内的出现顺序逐张请求。已保存图片跳过，失败不自动重试；打开聊天、刷新、开启开关时不补跑历史标记。切换聊天、换回复、关闭功能会撤销相关自动任务。自动生图使用现有服务配置与请求队列，会消耗接口额度。
- **生图回顾**：位于插件功能与使用偏好之间，默认查看当前角色卡的所有聊天图片，可切换全部角色卡，并通过角色卡名称标签筛选；同名卡独立分类，未归属图片单独收纳。每页最多 12 张，切页、关闭面板时释放旧预览；点击可全屏查看、下载、删除和查看生成属性。旧版楼层历史继续可用，新生成的绘图工坊试绘也会纳入；未打开角色卡时的试绘显示在全部图片中。旧版未保存的工坊试绘无法追溯，角色锚定图仍在角色库管理。
- **悬浮球状态**：生图队列工作时，缇娅将画匣支成画架作画，排队中的任务在画架后错开摆成空白画纸；悬停在她身上提示“正在生图 · 还有 N 张排队 · 点击打开菜单”，队列结束后恢复。回退使用原悬浮球时，照旧显示“绘制中”和动态圆环，悬停可查看排队数量。覆盖 NAI、GPT 的手动和自动生图，期间仍可拖动或点击打开菜单。

自动生图与留存选项随使用偏好保存，也纳入完整配置导出；导入确认中展示开关与保留期限。旧配置缺少这些字段时采用默认值。生成图片本身不包含在配置导出或 TT 扩展数据同步中。

## 生图接口配置

- **密钥配置**：选择官方或自定义渠道，在“配置”收纳盒中选择或命名连接，填写密钥后保存。保存后下划线连成粗线，保存按钮变灰；重新打开时密钥仍保留，默认隐藏，可点击“显示”查看。
- **生图配置**：选择 NAI V5、V4.5、V4 或 V3，以及尺寸、步数、引导强度、采样器、种子、噪声调度、CFG Rescale 和 SMEA。界面会禁用所选模型不支持的选项；种子 `-1` 表示随机。
- **预设尺寸**：提供竖图 832×1216、横图 1216×832、方图 1024×1024、高竖图 768×1344、宽横图 1344×768、896×1152、1152×896，以及自定义。新配置默认竖图；升级时保留既存尺寸。选择预设会联动宽高，手动修改宽高会同步匹配预设。
- **画师工坊**：填写正面、负面提示词，保存为命名配置，支持切换、更新和删除。提示词原样发送，不自动补充质量词或负面词。
- **生成图片**：点击底部生成区，完成后可预览并保存图片。配置页、角色图与楼层按钮共用当前页面的串行队列，按点击顺序生成；显示等待位置，支持取消排队。入队时固定本次参数与提示词，前项失败后继续后项，不自动重试；“取消等待”会停止本地请求，服务端任务可能仍在进行。

普通浏览器中，密钥、连接配置、参数和提示词保存在当前酒馆站点的 `localStorage`，不随 Git 发布，也不自动跨浏览器或设备同步。TauriTavern 的存储与同步见下节。密钥隐藏仅控制显示；浏览器存储中保存的是原值。清除站点数据会移除这些配置，专门的清除入口留待使用偏好设计。

NAI 页的自定义渠道需兼容 NovelAI 生图请求协议并允许浏览器跨域访问。仅填写域名时自动使用 `/ai/generate-image`；含路径的 URL 按完整接口地址使用，例如带 `/nai/` 前缀的反代应填 `/nai/ai/generate-image`。请求仍使用 PNG，收图兼容以下返回：

- 直接 PNG、JPG / JPEG、静态 WebP，以及含一张图片的普通 ZIP、ZIP64。按实际文件头识别格式；例如包内文件名为 `.png`、内容为 JPEG 时，以 JPEG 保存。压缩包仅含一个文件时也允许缺少图片扩展名。
- 原始 base64、图片 data URL，或 JSON 中的 `b64_json`、`base64`、`image`、`url` 字符串。支持单元素数组、`data` / `images` 包装（例如 `data: [{ b64_json: "…" }]`、`images: ["…"]`），不处理异步任务轮询协议。
- HTTP / HTTPS 图片地址（JSON 内或直接文本返回）。图片地址需允许跨域直接读取；请求不携带 API 密钥、Cookie 或来源信息，不跟随重定向，也不会重新发起生图。

保留 ZIP 体积、解压大小及 CRC 校验；单张图片最多 32 MiB、单边最多 4096 像素，base64 / JSON 响应最多 46 MiB。损坏或截断的数据、错误 JSON、HTML 网页和动态 WebP 不会当作图片保存。下载、历史、预览与角色图保留实际图片格式，生成属性显示输出格式。浏览器需支持 `DecompressionStream('deflate-raw')`，用于解压图片压缩包。

## GPT 生图与服务切换

- 在“生图 API”顶部选择 NAI 或 GPT（OpenAI 兼容），Gemini 与 Grok 收在“更多画笔”纸条里。连接、密钥配置、参数、模型列表、画师配置分别保存；旧版本配置归入 NAI。切换会同时选择模型 API 中对应服务的预设条目、编排、功能层启用状态与世界书挂载。模型 API 的连接和请求参数共用，GPT 预设初始不含文本指令，由用户导入或填写。
- GPT 模型名支持手填或点击“刷新列表”，以当前连接请求 `GET /v1/models`。列表只反映服务返回的名称，不保证每个模型都能生图；拉取失败仍可手填。修改连接会清空旧列表但保留已填模型名，刷新不自动替换模型。
- 官方使用 `https://api.openai.com/v1/images/generations`。自定义可填站点根、API base（如 `https://example.com/v1`）或完整的 `/images/generations` 地址，模型列表请求使用同一 base 的 `/models`。服务需允许浏览器跨域访问，并实现此 Images API 协议；聊天补全与异步任务轮询协议不属于本通道。
- GPT 默认竖图 1024×1536，提供横图、方图及自定义尺寸，质量可选 auto/low/medium/high/xhigh/max。实际支持范围以所选模型和服务为准。每次请求一张 PNG，读取 `data[0].b64_json` 或兼容站点的 `data[0].url`，也支持内嵌图片 data URL、换行或省略末尾填充的 base64。部分兼容站返回 JPEG 或静态 WebP 时，按真实文件内容校验并保留原始格式，继续使用原队列、局部画框、历史与全屏界面；下载扩展名与属性显示实际格式。图片限制为 32 MiB、单边不超过 4096 像素；损坏图片、动态 WebP、HTML 和错误 JSON 不会当作图片保存。取图片 URL 时不附带 API 密钥。
- GPT 发送用户原始场景描述，沿用现有独立 `@角色` / `#服装` 引用展开及画师正面串拼接，不把 `|` / `~` 转成 NAI 角色分栏，也不改写权重语法。GPT 不提供独立负面栏；约束由用户预设负责。插件不添加自然语言模板、不替用户改预设。角色图仅展示，不自动作为参考图发送。
- GPT 图片历史保存模型、实际尺寸和请求质量；旧 NAI 历史继续显示种子、步数及采样器等参数。两种服务共用串行队列，取消与超时不会自动重试付费请求。

接口依据：[OpenAI 图片生成](https://developers.openai.com/api/reference/resources/images/methods/generate)、[模型列表](https://developers.openai.com/api/reference/resources/models/methods/list)。

## Gemini 与 Grok 生图

- “生图 API”顶部默认只显示 NAI、GPT 和一张“更多画笔”纸条，点开纸条可选 Gemini 与 Grok。选中其中之一时纸条保持展开；切回 NAI / GPT 后自动收起。系统开启“减少动态效果”时纸条直接出现，不播放展开动画。
- 四个通道各自保存连接、模型列表、画幅参数与画师配置；模型 API 预设同样分四套，Gemini / Grok 首次使用时复制 GPT 预设。三者都是自然语言单串：不提供独立负面栏，不做 NAI 角色分栏。
- **Gemini** 可选三种接口协议：
  - Interactions（官方默认）：`POST https://generativelanguage.googleapis.com/v1beta/interactions`，请求体为 `input` + `response_format.{aspect_ratio,image_size}`。
  - generateContent：`{base}/v1beta/models/{模型}:generateContent`，请求体为 `generationConfig.imageConfig.{aspectRatio,imageSize}`。
  - OpenAI 兼容：仅限自定义中转站，走 `/v1/images/generations`。
  - 官方渠道只发 `x-goog-api-key`；自定义渠道同时带 `Authorization: Bearer`。`gemini-2.5-flash-image` 不发分辨率档位，`gemini-3.1-flash-lite-image` 固定 1K。返回内容依次读取 `output_image`、`steps`/`outputs` 中的图片块、`candidates[].content.parts[].inlineData`；没有图片时报告 `finishReason`（如安全拦截）。
- **Grok** 可选 xAI 原生（官方默认，`https://api.x.ai/v1/images/generations`）或 OpenAI 兼容协议。原生请求只发 `aspect_ratio`、`resolution`（1k / 2k）和 `response_format: b64_json`，不发 GPT 的 `size` 与 `output_format`；质量为 auto 时省略 `quality`，避免旧型号拒绝。
- 画幅：Gemini 比例 1:1、2:3、3:2、3:4、4:3、4:5、5:4、9:16、16:9，分辨率 1K / 2K / 4K；Grok 另有 auto 与超宽比例。AI 动态画幅的 7 种尺寸换算为：832x1216→2:3，1216x832→3:2，1024x1024→1:1，768x1344→9:16，1344x768→16:9，896x1152→Gemini 4:5 / Grok 3:4，1152x896→Gemini 5:4 / Grok 4:3。配置页显示的像素只是预估，历史记录写入返回图片的实际尺寸。
- 兼容协议下比例会换成约 1536 长边的 `size` 发送，实际支持范围以中转站为准。服务需允许浏览器跨域访问。
- 已知限制：旧版插件导入新版导出的配置文件可能报错（新增的 Gemini / Grok 字段旧版不认识）。迁移配置前请先把两边插件更新到同一版本。新版导入旧版文件不受影响。

接口依据：[Gemini 图片生成](https://ai.google.dev/gemini-api/docs/image-generation)、[xAI 图片生成](https://docs.x.ai/developers/model-capabilities/images/generation)。

## NAI 氛围参考（Vibe Transfer）

在“接口配置 → 生图 API → NAI”中，画师工坊上方右侧有“高级功能”按钮，默认折叠。展开后可管理氛围参考图：

- **添加**：上传 PNG / JPEG / WebP（单张 8 MiB 以内），或导入 NAI 官网导出的 `.naiv4vibe` / `.naiv4vibeBundle`；“导出合集”生成 `.naiv4vibeBundle`。
- **参数**：每张可单独启用，调整参考强度（默认 0.6）与信息提取度（默认 1.0）；“强度总和超过 1 时自动归一化”默认开启。
- **V4 / V4.5**：普通图片首次生图时调用 `/ai/encode-vibe`（每张 2 Anlas），结果按图片 SHA-256 + 模型 + 信息提取度缓存在 IndexedDB，命中缓存不再编码。改强度不需要重新编码，改信息提取度或换模型需要。导入文件自带的编码直接使用。自定义渠道开启自动补全时把 `/ai/generate-image` 换成 `/ai/encode-vibe`。
- **V3**：直接发送原图，无需编码。
- **V5**：NAI 官方尚未开放，面板会提示，生图时自动跳过。
- **张数**：最多 16 张；启用超过 4 张时，NAI 每多一张额外收取约 2 Anlas，面板会提示。

氛围图只保存在当前浏览器，暂不随配置迁移或 TT 同步。

## TauriTavern 配置同步

支持 TT 公开的 [Extension Store API](https://github.com/Darkatse/TauriTavern/blob/main/docs/API/Extension.md)。支持该接口时，画匣自动将配置保存在 TT 的原生扩展数据中；在 TT 同步界面选择“扩展数据”即可带走生图连接与参数、模型连接与预设、画师串、角色外貌与服装库、角色图、上传世界书及挂载选择。页面记忆与悬浮球位置仍随酒馆设置同步。生成图片历史不在此次同步范围内。

首次接入会校验并迁移当前设备的旧浏览器配置，保留原始记录；已有原生配置（包括空库）优先使用。读取失败不会被当成空数据覆盖，写入完成后才提示保存成功。世界书与角色图先写入独立数据文件，最后更新目录；旧版本文件保留，避免同步途中移除仍被引用的内容。TT 拉取后重载页面，插件重新读取同步后的配置。旧 TT 缺少所需接口时保留本机模式，可在使用偏好中查看提示。

使用偏好中的“同时同步 API 密钥”默认关闭：同步文件不包含密钥，本机按连接标识、渠道与服务地址恢复自己的密钥；另一台设备需自行填写。开启后，已保存的生图和模型 API 密钥会写入 TT 扩展数据，跟随该同步范围；它不使用 TT 单独的密钥同步分类。关闭后清除当前原生配置中的密钥并保留本机副本；其他设备需完成下一次同步，外部备份不受此开关影响。

## 模型 API 与预设

- **连接方式**：跟随酒馆主 API 时使用当前聊天补全连接；不修改主设置，不自动带入主聊天历史、主预设或世界书。需要酒馆提供 `ChatCompletionService`，文字补全型主 API 暂不支持。
- **自定义接口**：填写 OpenAI 兼容接口的 URL、API Key 和模型名称；右侧刷新通过酒馆后端 `/api/backends/chat-completions/status` 获取模型列表，模型仍可手动填写。URL 可填 `/v1` 基址或完整 `/chat/completions` 地址，仅域名时默认补 `/v1`。模型请求统一经过酒馆后端 `/api/backends/chat-completions/generate`，密钥随本次请求传给酒馆后端，不修改主连接。
- **生成参数**：独立设置 max tokens、温度，以及非流式、流式、假流兼容。假流兼容发送流式请求，收齐正文后统一交付；接受 SSE、完整 JSON、JSON 数组、心跳后返回的 JSON 或 SSE 中一次返回的完整文本。空的结束消息不会清空已有正文，取消或超时会主动停止读取；不使用模拟逐字动画，不自动重试。
- **预设编排**：左侧列出条目与发送顺序，右侧编辑名称、消息角色及内容。可新增、启用、关闭、上下移动或删除文本条目；世界书、标签锚定与最新正文也是独立的可移动条目。功能条目从数据源读取，可关闭；最新正文固定保留。点击“保存配置”后生效，关闭后重新打开密钥默认隐藏。
- **导入预设**：支持酒馆 `prompts/prompt_order` 及明确的 `{head,tail}` 结构。旧配置按“原头部 → 功能层 → 最新正文 → 原尾部”迁移；未声明头尾的导入文件保持原顺序，可在左侧移动功能条目和最新正文。最多导入 10,000 条，列表每页展示 100 项，翻页不改变发送顺序；单个预设 JSON 文件仍限 2 MiB。导入、保存与配置迁移使用相同条数上限。导入仅更新草稿，保存后生效。酒馆占位 marker 保留展示并禁用；预设文本支持 setvar/getvar，其他宏保留为普通文本。损坏文件不替换原配置。
- **世界书层**：从玩家上传到插件的世界书中手动勾选条目，可挂载多本书。上传入口在“插件功能 → 世界书”，预设右侧也可调整挂载。启用并保存配置后，蓝灯条目常驻，绿灯条目在本次发送的正文命中主关键词后激活；保留次关键词与 AND ANY、AND ALL、NOT ANY、NOT ALL 逻辑，支持大小写、整词与 `/正则/flags` 匹配。默认不区分大小写、不要求整词。只扫描当前正文副本（按上下文隐藏设置排除配图块），不扫描预设、临时插入点编号或其他世界书条目，不做递归激活或宏展开。每次请求重新读取本地数据，仅发送激活条目的原文，禁用及空条目不发送。旧版上传时未保存触发字段，旧书会提示重新导入原文件并重新选择条目，不会自动当成蓝灯发送。
- **标签锚定层**：请求前读取角色库与通用服装库，按 INI 分段发送正式名、全部别名、固定外貌（base）、当前选中的默认服装（default），以及每套专属服装的名称和 tag；通用服装列在末尾。未选默认服装时 default 留空。右侧可预览和刷新，保存角色或通用服装后更新预览。角色调用输出规则仍由用户预设负责，插件不追加指令。
- **上下文隐藏**：默认开启“从 AI 上下文隐藏配图标记”。为酒馆添加一条固定 ID 的原生 `promptOnly` 正则，排除用户/助手消息里完整的 `<img>…</img>` 块，覆盖原生主聊天和文本补全生成；插件自己的 AI 生图请求也过滤正文副本。楼层原文、按钮与预设指令保持不变。规则不匹配带属性的真实 HTML 图片或未闭合块，其他正则保持原样。关闭并保存会禁用本插件的规则；原生正则被关闭或不兼容时，设置页会显示未生效原因。绕过酒馆原生生成流程的其他扩展请求不保证受该规则影响。

打开功能条目会读取世界书或本地锚定库以显示预览；世界书预览按当前最新 AI 回复匹配，尚无可用正文时会提示，正文变化后可点击刷新预览。点击刷新才获取模型列表。上述读取不请求 AI 模型。

## 标签锚定与世界书

功能层顶部用相连的“标签锚定 / 世界书”按钮切换页面。标签锚定内部有“本轮生图”“锚定配置”“通用服装库”，分别管理本轮图片、角色固定外貌与专属服装、可跨角色使用的服装。

- **本轮生图**：读取当前聊天最新 AI 回复中各个配图标记的已保存图片，包括同一标记的图片历史。图片与实际发送的正面 tag 放在一起；点击后带入角色图和 tag，填写角色中文名称。切换聊天、swipe 或编辑楼层后重新读取，旧图片不会归到新楼层。
- **筛选外貌**：点击“筛选外貌 tag”，手动勾选要保留的标签，也可直接编辑文本。外貌应只留下发色、发型、瞳色等固定特征；场景、动作、画师词和服装由用户筛除。括号及 `::` 权重组作为整体选择。本版不调用 AI 自动提取，不处理多人图的特征归属。
- **锚定配置**：按“角色 → 服装1、服装2”展示。可新建、修改、删除角色，上传或移除角色图，添加、修改、删除服装，并选择当前服装。编辑后点击“保存角色”生效，删除服装前可通过放弃草稿恢复。角色名称不能重复，服装名称在同一角色内不能重复。
- **别名与称呼**：在角色编辑器中填写多个称呼，以换行或中英文逗号分隔，最多 20 个。每个称呼须含汉字，遵守角色名称的格式限制。正式名和别名都能展开同一套外貌与服装，也支持 `别名/服装名` 和 `别名/无服装`；只匹配独立的完整 tag，不替换句子中的部分文字。重复别名、与正式名相同或占用其他角色称呼时会提示冲突。旧角色无需重新创建，别名默认为空。
- **角色负面提示词**：点击“添加负面提示词”才展开输入区，填写后点击“保存角色”；已保存的负面词再次编辑时直接显示，可移除。NAI 单串生图时与全局负面词合并，多角色分栏时只加入调用该角色的栏位，与该栏的 `~` 负面词合并。同一栏重复调用角色或其别名只添加一次；零或负数权重调用不附加角色负面。负面词不作为正面展开、不加入模型 API 的角色目录。GPT 不支持独立负面词，调用含负面词的角色时会提示清空或切换 NAI。旧角色默认留空，完整配置迁移与 TT 同步保留该字段。
- **生成角色图**：在锚定配置的角色编辑器中点击“生成角色图”，使用当前服务已保存的连接、参数、画师词及草稿中的固定外貌、当前服装；NAI 合并画师负面词与角色负面词；不自动添加标签。与其他生图入口共用队列，可取消等待。结果先进入角色草稿，点击“保存角色”后持久化；切换设置页面可后台继续，失败保留原图。
- **通用服装库**：新建、编辑或删除“服装名称 + 服装 tag”，保存后可用 `#服装名` 调用。与角色专属衣库分开保存；角色和通用服装的编辑草稿在页签之间切换时各自保留。
- **生成前展开**：以逗号或换行分隔，单独填写 `@莎莉`，展开固定外貌与默认服装；`@莎莉:日常装` 指定一套服装，`@莎莉:无服装` 只展开固定外貌。别名同样可用。`@莎莉, #旅行装` 展开固定外貌与已保存的通用旅行装。新调用支持 `{}`、`[]`、`1.2::…::` 等完整权重包裹，权重和无关 tag 保持原样；未知 `@角色`、服装或 `#通用服装` 会报错，阻止本次请求。只展开一次，不递归解释保存的 tag 中的引用。
- **默认服装避让**：只检查正面词中独立的 `nude`、`completely_nude`、`topless`、`bikini`、`swimsuit`、`nightgown`、`towel`，或有效的 `#通用服装` 调用。大小写、空格和下划线等价，支持权重包裹；零或负数权重中的词不触发。命中后，未指定服装的 `@角色` 只展开 base。明确指定的专属服装保留，不自动删除用户写入的 tag。`nude makeup`、`no swimsuit` 等非完整匹配不触发。单串按整条场景判断；分栏时，各角色仅检查自己的正面栏，全局、其他角色、负面词及后来拼接的画师串不会影响该角色的默认服装。
- **旧调用兼容**：无前缀的 `莎莉`、`莎莉/日常装`、`莎莉/无服装` 仍按原规则展开，不参与新的默认服装避让；旧写法带权重时仍保持原文。名称须含汉字，不能包含逗号、换行、斜杠、英文括号、反斜杠或 `::`；专属服装名称“无服装”保留给仅外貌调用。未知无前缀角色名仍保持原文。旧角色、服装和别名无需重新创建。
- **提示词组合**：先识别原始场景的全局与角色分栏，再分别展开正面词中的角色引用；画师工坊正面词只拼接到全局末尾，全局负面词仍独立使用。配置页生成也支持名称展开与分栏。生成历史分别记录实际发送的全局和各角色正负面词，另存原始场景词；排队中的任务不随后续角色编辑改变。不自动改写正文或导入预设，名称需由预设输出或手动填入生图 tag。

普通浏览器中，角色、专属服装和角色图保存在当前酒馆站点的 IndexedDB，通用服装使用插件专属 localStorage；刷新后保留。TauriTavern 中这些配置使用原生扩展数据存储，可随 TT 同步。角色图与原生成图片独立保存，删除一方不会删除另一方。上传角色图支持不超过 10 MB 的 PNG、JPEG 或 WebP；角色图仅用于配置展示，不作为生图参考图发送。

模型 API 中的标签锚定预览示例：

```ini
[莎莉 | 白峰理沙]
base = sally (bofuri), {{very long grey hair}}, pale blue eyes
default = white dress, sandals
日常装 = white dress, sandals
睡衣 = linen nightgown

[@通用服装库]
旅行装 = cloak, boots
```

tag 中的权重符号原样保留，多行内容以缩进续行；存在分段歧义的名称使用引号展示。base 内容由用户维护，插件不自动筛除其中的服装、表情或动作。

关键词激活规则参考 [SillyTavern World Info](https://docs.sillytavern.app/usage/core-concepts/worldinfo/)；当前不执行概率、延迟、黏性、递归等完整酒馆激活流程。

世界书页支持一次多选 JSON 文件，每个文件不超过 20 MiB：标准 `entries` 对象、`entries` 数组，以及 `character_book`（含角色卡 `data.character_book`）格式。每本最多 10000 条，缺少数组条目标识时使用导入位置作为稳定标识。同名书另存为递增后缀，不覆盖旧书。上传后可在挂载收纳框中同时管理多本世界书：已挂载的书名始终显示，展开或收起只控制待选列表；点击书名切换条目，当前选中的书名以强调色显示。展开后点击未挂载的书即可挂载全部可用条目，再按需逐条勾选；点击书名旁的 × 仅取消该书挂载，保留上传文件。挂载与移除在点击“保存配置”后持久化。书名较多时自动换行撑开，长书名可折行。删除书库文件仍使用独立的“删除世界书”操作，并同时移除挂载。文件内容保存在当前站点的插件专属 IndexedDB，刷新后保留，不读取或改动酒馆原生世界书。

批量导入按选择顺序逐本校验和保存，显示当前进度；单个文件失败不影响其他文件，完成后列出成功书名和失败文件原因。同名书仍另存，不自动挂载。切换或关闭页面会停止后续文件，已确认保存的书保留，结果会注明尚未导入的文件数量。

## 配置迁移与分享

“使用偏好”的配置导出提供四个直接可点的范围按钮：全部配置、画师串、预设、世界书；“开始使用”的系谱图和介绍可直接跳转到此处，也可进入标签锚定和世界书页面。

- **所有配置**：导出 NAI/GPT 两套已保存的生图 API 连接及参数、画师串、对应模型预设编排与共用模型 API 连接、角色锚定（别名、外貌、专属服装与角色图）、通用服装库、上传的世界书及挂载关系、使用偏好。已生成的图片历史不包含在配置文件内。
- **仅画师串**：导出命名画师配置、当前正面与负面词及选用状态，用于分享；不含接口、密钥、参数或其他配置。
- **仅预设**：导出当前预设名称、头尾文本条目、发送顺序、功能层启用状态与配图标记设置；不包含 API 连接、参数或世界书内容。
- **仅世界书**：导出上传的世界书、蓝绿灯及关键词规则、已保存的挂载选择；不包含预设或 API 配置。
- **密钥与 URL 可选**：完整导出可勾选“包含 API 密钥和相应 URL”，默认关闭。勾选后两者以明文写入 JSON，文件名带“含密钥和URL”；未勾选时 NAI / GPT 当前连接及全部保存连接、共用模型连接的 key 和 url 字段一并清空，仅处理导出副本。完整导入这类文件后需重新填写密钥，自定义接口还需填写地址。配置名称、预设和世界书正文保留原文。
- **先校验再确认**：选择文件不会立即写入。插件检查格式版本、参数范围、重复标识、角色图格式与世界书挂载关系，随后展示各配置类别、数量、名称及实际包含的密钥和 URL 数量，密钥内容不显示。旧版不含密钥但保留 URL 的文件仍可导入，并如实显示 URL 数量。最大文件大小为 128 MiB。
- **确认覆盖**：完整文件替换对应配置、编辑草稿、角色库和世界书库；画师串文件只替换画师列表、当前正负面词及选用状态，保留接口配置和接口草稿。预设文件只替换预设和标记设置，世界书文件只替换书库与挂载，保留其他配置及接口草稿。导入后刷新页面内的配置缓存即可使用，无需刷新酒馆。存储失败会尝试恢复导入前的配置；如恢复也失败，会明确提示未恢复状态。

新版完整配置文件包含两套服务；画师串和预设单独分享时记录当前服务类型，导入确认页展示目标，旧版文件归入 NAI。世界书文件保存共用书库及两套挂载关系。

导出前请先保存其他页面的修改。预设内容、画师词及世界书正文按原文迁移，不追加或改写模型指令。文件读取与校验在当前浏览器完成；使用偏好沿用酒馆的延迟保存，插件可确认已提交保存，但无法确认酒馆后端稍后的持久化结果。

“使用偏好”底部提供更新历史，按日期展示功能与修复摘要，最近一组默认展开，旧记录可点击展开。完整配置导入会预先校验角色正式名与别名冲突，并在确认列表中显示别名数量；旧版备份未包含别名时仍可导入。

通用服装随完整配置迁移，导入确认页展示数量与名称。旧版完整备份没有通用服装字段时按空库导入，并明确提示会替换当前通用服装库；只导入画师串、预设或世界书时保留它。

## 角色分栏协议

NAI 模式下，楼层生图标记和生图配置页的正面词可选用 `全局 | 角色一 | 角色二`。插件识别完整格式时启用分栏；普通提示词或分栏格式不完整时，保留整段内容按单串生成，不因格式拦截请求。没有新增开关或预设指令；AI 的输出规则由用户预设负责。

```text
2girls, tavern, sitting at table, warm light | girl, @莎莉, holding cup, smiling | girl, @柜台小姐:便服, waving ~ glasses
```

- 第一栏填写人数、场景、整体互动、构图与光影；角色的固定外貌、服装、动作、表情放在后续各栏。人数不会由插件自动补齐，也不会按角色名称自动拆栏。
- 完整分栏中，每个角色栏可用一个 `~` 分隔专属正负面词：`角色正面 ~ 角色负面`。负面可省略或留空；角色负面作为普通 NAI tag 原样发送，不展开 `@角色` 或 `#通用服装`。普通单串中的 `~` 原样保留，不自动将后半段移入负面词。
- 角色引用和服装避让在每个正面栏内独立执行。例如 `@莎莉, #旅行装` 只跳过这一栏的默认服装，不影响下一栏的角色。画师串只加到全局，角色栏不重复添加。角色库与通用服装库每次生成只读取一次，入队后冻结请求。
- 仅 ASCII `|`、`~` 在权重括号或数字权重组之外、且未被反斜杠转义时参与分栏识别。`{}`、`[]`、`()`、`<>`、`1.2::…::` 内的符号保留原意；括号或数字权重未闭合而无法确认分隔边界时，使用普通单串。
- 名称本身含 `|`、`~` 时，调用写成 `@角色\|别称:衣服\~名称`；JSON 中反斜杠须写成 `\\`。只在引用名匹配时解码，普通 tag 的转义保留。保存的锚定 tag 和画师串不会被再次解释为分栏。`source#hug`、`target#hug` 等原生动作 tag 原样保留。
- 空栏、尾随 `|`、同栏多个 `~` 或全局栏出现 `~` 时，整段按普通正面词处理；不删词、不猜测角色边界，仍执行现有标签锚定展开和画师串拼接。未知角色/服装及存储、连接、参数错误仍会明确提示。
- V4/V4.5 最多 6 个角色栏，V5 最多 22 个；超出上限或使用 V3 时同样回退普通单串。有效分栏请求使用 `v4_prompt.caption.char_captions` 与对应的负面分栏，同序保留空负面栏。`use_coords: false`，由模型选择站位，不强制左右坐标。

生成属性可分别查看全局和每个角色的实际正负面词，旧图片记录仍可读取。本轮生图的 tag 展示汇总各正面栏，筛选角色外貌仍由用户手动操作。分栏有助于区分角色特征，不保证生成结果完全避免特征混合。协议依据 [NovelAI 多角色说明](https://docs.novelai.net/en/image/multiplecharacters/) 与 [请求结构](https://image.novelai.net/docs/doc.json)。

## AI 动态画幅与预设变量

生图配置的画幅区可切换“固定画幅 / AI动态画幅”。模式直接取自当前 NAI / GPT 预设中两个条目的启用状态，按以下名称识别（📐 图标可省略，空白与竖线的全半角差异不影响识别）：

- `📐 格式｜默认画幅·三字段输出协议`
- `📐 格式｜AI动态画幅·四字段输出协议`

名称优先；也支持 `output-format-fixed-size` / `output-format-ai-size` 条目 ID 兜底，导入文件中的 `identifier` 会转为 ID。只有完整的协议名称或这两个 ID 参与联动，普通说明条目不受影响。

画幅按钮与预设里的协议勾选双向联动：任一处切换都会立即保存这两组条目的互斥状态，另一处与实际生图读取同一份配置。关闭两组协议时回落固定画幅。切换只保存协议启用状态，其他草稿继续等待“保存配置”；新导入、添加或改写的协议需先保存一次配置。保存期间两处开关暂时禁用，依赖画幅模式的新请求需等待同步完成；保存失败恢复切换前的选择。NAI / GPT 分别同步。未导入目标条目时会提示，不创建提示词。旧预设保持固定画幅，导入时若两组都开启则保留固定模式。

动态模式允许每个 JSON 对象增加 `size`，支持 `832x1216`、`1216x832`、`1024x1024`、`768x1344`、`1344x768`、`896x1152`、`1152x896`。固定模式使用设置中的宽高；动态模式缺失或无效尺寸时也回退到它们。尺寸只覆盖单张请求，不改全局配置；试绘和角色图继续使用设置中的画幅。自定义服务最终支持的尺寸由服务端决定。

尺寸保存在新配图块概括行之后的专用注释 `<!-- witch-paintbox:size=832x1216 -->` 中，刷新和再次生图可恢复，注释不进入绘图提示词。旧标记原样兼容，已有图片历史不改写。

预设文本可以使用 `{{setvar::名称::值}}` 和 `{{getvar::名称}}`。例如在格式条目引用 `{{getvar::生图数量要求}}`，把 `{{setvar::生图数量要求::3}}` 放到后方独立条目；值也可以是多行文字。插件先按发送顺序收集本轮启用条目的定义，再替换引用，同名以最后一处定义为准。定义本身不发送，只有定义的条目不会产生空消息。

变量每次请求重新建立，不读写酒馆变量；正文、世界书和标签锚定不执行这些宏，替换值中的宏也不递归执行。未定义变量或宏格式错误会明确指出条目，停止本次模型请求。插件保留预设源文，不自动添加数量、画幅选择或其他模型指令。

## AI 处理最新回复

1. 在模型 API 页导入或填写预设，调整左侧条目顺序，按需挂载世界书，开启“解析配图标记”并保存。
2. 点击悬浮球，选择“AI生图”；键盘 Enter／空格也可打开菜单。选择“设置”进入主界面，拖动不会触发处理。
3. 插件按真实换行记录可插入位置，在发给 AI 的正文副本中加入 `【插入点 P001】` 等编号。代码块、已有图片标记和 HTML 标签内部不提供插入点。原楼层不写入这些编号；使用已保存的预设与模型参数，不追加系统提示词。
4. 导入预设负责让 AI 返回下方 JSON 数组。插件校验编号与配图内容，按原始位置从后向前插入完整标记，保留原文的每个字符；不要求 AI 复述正文。无效编号、空提示词或格式错误会阻止整次写回；等待期间切换聊天、出现新楼层、切换 swipe 或编辑原文也会阻止写回。
5. 插入后更新原楼层及当前 swipe，并保存到原聊天。服务端确认保存后显示成功；保存未获确认会提示状态，不自动重试。提交保存后不能再取消；提交前可取消 AI 请求。

“指定插图”沿用同一模型 API、预设与保存流程。正文在连续纸面展示，提供三种选取方式：**正文原文**按自然段点击，**选取文段**按 3、5、8 个非空原文行划分，**选取句子**按句末标点细分并定位到真实句尾。代码、已有图片及不能安全定位的部分保留显示，不在其内部插入。

点击内容会加入配图清单，每项一张；可以继续选取、单独移除或清空，再统一提交。切换方式、更改分段行数或关闭窗口会保留当前清单，重叠范围不重复加入。手机清单可折叠；重新读取正文会清空旧清单，成功保存后也会清空，避免使用旧位置再次提交。

提交时保留完整正文，只标注清单中的候选位置，并在 `input` 正文末尾追加 `<指定插图位置锁定>` 块。单点项指定一个编号；范围项列出首尾编号与实际可用点，要求 AI 从其中选一个 `at`，每项恰好返回一张。遗漏、重复或返回清单以外的位置均不写回。锁定块仅用于本次模型请求，不保存到楼层，也不改写预设；普通“AI生图”不追加该块。请求前与写回前均核对楼层快照，选择后正文变化时需重新读取。

AI 返回格式（配置页也可展开查看）：

```json
[
  { "at": "P001", "summary": "图片内容概括", "prompt": "该场景的生图提示词" }
]
```

`at` 必须是本次正文副本中提供的编号；`summary` 为单行概括；`prompt` 仅包含场景提示词。可返回多个对象，同一位置按数组顺序插入；空数组表示没有配图。接受纯 JSON 或完整的 JSON 代码围栏，拒绝额外解释和整篇改写正文。原有预设如返回完整正文，需要自行调整输出格式；插件不会改写导入预设。

无尺寸标记使用以下四行结构（每个块均须闭合，提示词可占多行；动态尺寸标记会多一行专用注释）：

```text
<img>
[图片内容概括]
该场景的生图提示词
</img>
```

每块在楼层中显示为独立生图按钮，围栏代码中的示例不解析。按钮只存在于显示层，聊天中保存的仍是原文与标记。点击时使用当前生图服务和对应配置；NAI 按上述分栏协议组装，GPT 发送展开锚定后的描述，画师正面词在各通道末尾追加。AI 处理阶段不读取画师正负面词；自动生图需要在使用偏好中开启。

配图按钮在已显示的楼层中按完整题文与提示词定位，只替换对应片段，不重建整层正文；关闭解析也只恢复该片段。定位不会跨过 iframe、代码块或其他交互控件，原有标记被隐藏或定位不明确时会跳过，其余可独立显示。

AI 插入采用增量挂载：服务端确认保存后，才更新内存里的正文与当前 swipe，并通知插件自己的配图界面；不调用整层重绘，也不发送会重新加载 HTML 前端的酒馆渲染事件。插件使用已校验的原文插入位置，匹配相邻完整行并插入画框。如果位置已被其他美化转换、无法可靠定位，则在本楼层末尾显示临时配图区，仍可生成、查看和下载图片。后续正文位置可确认，或酒馆因用户操作正常重绘时，再恢复到相应位置并复用画框与进行中的请求。普通图片生成完成只更新本插件画框；不会把模型尚未闭合、未经校验的流式内容写入正文。

方括号里的场景概括会识别为画题，“画题”和标题两行居中。点击标题可折叠或展开图片；标题右侧的“再次生图”在折叠时也能使用，点击按钮不会切换折叠状态。排队、绘制和出错时，折叠栏下方仍显示进度、取消操作或错误说明。两处生图按钮共用请求状态与队列，再绘会加入同一标记的历史，并保留旧图。

画框采用暖纸底、金茶双层细轨和四角金属护角，参考天气占签与属性检定的边框结构。宽度取画题（含右侧操作）与图片显示宽度中较大的值，并限制在楼层可用宽度内；图片宽度从预设尺寸等比计算，保留既有 560px 显示高度上限，窄屏继续等比缩小。状态文字不参与撑宽画框。生图按钮底色仍根据所在页面背景调整，文字固定为白色。

点击图片打开全屏查看器，完整图片按剩余空间等比显示，展开属性面板时自动适配。上方显示“当前序号 / 总张数”，其下为横向历史缩略图；可下载或删除当前图片。点击“生成属性”从底部展开面板，查看该图实际使用的模型、尺寸、步数、种子、采样参数、生成时间与完整正负提示词。左右方向键切图，Esc 先收起属性面板，再关闭查看器。

图片 Blob 与生成属性保存在当前酒馆站点的浏览器 IndexedDB，刷新后恢复同一标记的历史；不存入聊天附件，不跨浏览器或设备同步。存储失败会明确提示，仍可立即下载本次图片；清除站点数据会删除本地历史。楼层重渲染时保留同一标记的请求与预览，切换聊天、回复版本、删除标记或关闭解析会释放预览并取消相应排队项，已保存的历史仍保留。删除图片只删除选中的历史记录，不会删除生图标记或其他图片。

历史按聊天、原生回复时间身份与完整生图标记区分，不使用可变的楼层下标。导入记录缺少或重复时间身份时会提示仅保留当前页面，避免串图；继续生成等操作若改变了原生回复时间，或手动修改了生图标记，则按新的归属读取历史。

每条回复最多解析 64 个块；AI 处理支持原文最多 256 Ki 字符，返回内容及插入后正文最多 512 Ki 字符。插入块沿用原文换行风格，并在需要时补充分隔换行；原有空格和换行保持原样。

新增功能时，在 `src/pages.ts` 登记页面，在 `src/views.ts` 添加页面内容与对应系谱图入口。

功能通过 `registerFeatureLayer({ id, title, messages })` 注册，返回的函数用于注销。新的外部功能需由用户启用；内置世界书与标签锚定条目默认开启，未选择世界书时不发送世界书内容。`messages(context)` 接收本次输入消息、只读配置快照、可选数据和取消信号，返回消息数组。`runConfiguredModel(context, onText?)` 按保存的 `promptOrder`（与左侧列表一致）组装并请求模型；关闭的条目不读取、不发送，`onText` 接收截至当前的完整正文。该入口不自动添加模型指令。

扩展各处通过 `src/pet-events.ts` 的 `emitPetEvent` 报告进度，桌宠通过 `onPetEvent` 订阅。事件类型包括：`process`（读取、思考、保存）、`image`（`start` / `queued` / `generating`，附带来源 `floor`、`auto`、`config`、`portrait`，以及 NAI 分栏数、排队位置、图片宽高）、`end`（`done` / `failed` / `cancelled` / `dropped`，附带错误类别 `fault` 与完成的图片）、`history`（图片历史是否保存）、`frames`（楼层画框挂载）、`auto`（自动生图等待数）、`ui`（菜单与面板开关）、`stop`。每个 `start` 恰好对应一个 `end`；监听者抛错不会打断生图、保存或渲染。错误可通过 `withFault(error, kind)` 标记类别并由 `petFault(error)` 读出，类别包括 `reference`、`setup`、`host`、`auth`、`quota`、`busy`、`network`、`timeout`、`format`、`decode`、`storage`、`unknown`。`src/pet-targets.ts` 提供楼层画框在页面上的坐标及是否在视野内，供图片飞入动画定位。构建仍为 `npm run build`，`dist/` 一并提交，无新增外部依赖。

原生路线（`src/sifang-image-control.ts`）与酒馆楼层画框报告同样的桌宠事件，包括 `image` 的开始、排队、绘制，`end` 的完成、失败、取消、丢弃，以及 `history`。`ui.imageMarkerRect({ saveId, node, id })` 返回宿主画框在插件窗口坐标中的位置 `{ left, top, width, height, view }`，`view` 为故事栏可见的范围，画框未画出时返回 `null`；插件在图片完成后约 8 秒内每 100 毫秒读取一次，供飞行定位。`ui.imageMarker` 新增可选字段 `veiled`，为 `true` 时宿主保留图片位置但暂不显示，最多 4 秒后插件自动取消。不支持这两项的宿主会忽略 `veiled`，缇娅改为将图收回画匣，其余功能不受影响。

## Git 发布与安装

将**本目录内容**作为独立仓库的根目录，确保 `manifest.json` 位于仓库根。每次修改 TypeScript 后执行构建，并一同提交 `dist/` 和 `style.css`；用户安装时不需要编译。

仓库发布后，用户在酒馆“扩展 → 安装扩展”中填写该 Git 仓库地址，然后刷新页面，点击站在页面右下角的缇娅（或回退状态下的“绘”悬浮球）进入。

此目录不依赖角色卡工程、MVU 或酒馆助手。
