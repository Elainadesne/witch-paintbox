# 魔女画匣

每次生图，都是魔女看板娘施展的一次绘图魔法。

独立的 SillyTavern 前端扩展，提供可拖动悬浮球、四个主板块、从上向下展开的金字塔系谱图，以及使用偏好的保存。

生图 API 已接入 NovelAI，模型 API 支持酒馆聊天补全连接或自定义接口。配置页采用下划线与留白分区；两类 API 在窗口右上角切换。

看板娘的姓名、性格、外观与具体施法表现待讨论确定。本版尚未加入立绘或动画。

## 生图配置

- **密钥配置**：选择官方或自定义渠道，在“配置”收纳盒中选择或命名连接，填写密钥后保存。保存后下划线连成粗线，保存按钮变灰；重新打开时密钥仍保留，默认隐藏，可点击“显示”查看。
- **生图配置**：选择 NAI V5、V4.5、V4 或 V3，以及尺寸、步数、引导强度、采样器、种子、噪声调度、CFG Rescale 和 SMEA。界面会禁用所选模型不支持的选项；种子 `-1` 表示随机。
- **预设尺寸**：提供竖图 832×1216、横图 1216×832、方图 1024×1024、高竖图 768×1344、宽横图 1344×768、896×1152、1152×896，以及自定义。新配置默认竖图；升级时保留既存尺寸。选择预设会联动宽高，手动修改宽高会同步匹配预设。
- **画师工坊**：填写正面、负面提示词，保存为命名配置，支持切换、更新和删除。提示词原样发送，不自动补充质量词或负面词。
- **生成图片**：点击底部生成区，完成后可预览并保存图片。配置页与楼层按钮共用当前页面的串行队列，按点击顺序生成；显示等待位置，支持取消排队。入队时固定本次参数与提示词，前项失败后继续后项，不自动重试；“取消等待”会停止本地请求，服务端任务可能仍在进行。

密钥、连接配置、参数和提示词保存在当前酒馆站点的浏览器 `localStorage`，不随 Git 发布，也不跨浏览器或设备同步。密钥隐藏仅控制显示；浏览器存储中保存的是原值。清除站点数据会移除这些配置，专门的清除入口留待使用偏好设计。

自定义渠道需兼容 NovelAI 生图协议并允许浏览器跨域访问。仅填写域名时自动使用 `/ai/generate-image`；含路径的 URL 按完整接口地址使用。浏览器需支持 `DecompressionStream('deflate-raw')`，用于解压接口返回的 PNG 压缩包。

## 模型 API 与预设

- **连接方式**：跟随酒馆主 API 时使用当前聊天补全连接；不修改主设置，不自动带入主聊天历史、主预设或世界书。需要酒馆提供 `ChatCompletionService`，文字补全型主 API 暂不支持。
- **自定义接口**：填写 OpenAI 兼容接口的 URL、API Key 和模型名称；右侧刷新通过酒馆后端 `/api/backends/chat-completions/status` 获取模型列表，模型仍可手动填写。URL 可填 `/v1` 基址或完整 `/chat/completions` 地址，仅域名时默认补 `/v1`。模型请求统一经过酒馆后端 `/api/backends/chat-completions/generate`，密钥随本次请求传给酒馆后端，不修改主连接。
- **生成参数**：独立设置 max tokens、温度，以及非流式、流式、假流兼容。假流兼容发送流式请求，同时接受 SSE、完整 JSON 或 SSE 中一次返回的完整文本；不使用模拟逐字动画，不自动重试。
- **预设编排**：头部和尾部支持多条消息、角色选择、启用与删除，正文默认留空。中间为功能层接口。点击“保存配置”后存入当前浏览器，关闭后重新打开密钥默认隐藏。
- **导入预设**：选择 JSON 文件，显示预设名称、条目名称、角色、启用状态和正文。支持酒馆 `prompts/prompt_order` 及明确的 `{head,tail}` 结构；没有头尾声明时按原顺序放入头部，通过“功能层插入位置”选择正文与功能内容的插入点。导入仅更新草稿，保存后生效。酒馆占位 marker 保留展示并禁用，宏保留为普通文本。损坏文件不替换原配置。
- **功能层快捷入口**：预设尾部可前往功能层配置，再返回模型 API。当前只提供扩展接口；世界书选择和具体功能尚未接入，也不会自动读取世界书。

打开配置页只读取本地配置；点击刷新才获取模型列表，不会自动请求模型。

## AI 处理最新回复

1. 在模型 API 页导入或填写预设，选择功能层插入位置，开启“解析配图标记”并保存。
2. 长按悬浮球约 0.6 秒，选择“AI 处理最新回复”；右键或键盘菜单键也可打开此菜单。普通点击仍打开主界面，拖动不会触发处理。
3. 插件按真实换行记录可插入位置，在发给 AI 的正文副本中加入 `【插入点 P001】` 等编号。代码块、已有图片标记和 HTML 标签内部不提供插入点。原楼层不写入这些编号；使用已保存的预设与模型参数，不追加系统提示词。
4. 导入预设负责让 AI 返回下方 JSON 数组。插件校验编号与配图内容，按原始位置从后向前插入完整标记，保留原文的每个字符；不要求 AI 复述正文。无效编号、空提示词或格式错误会阻止整次写回；等待期间切换聊天、出现新楼层、切换 swipe 或编辑原文也会阻止写回。
5. 插入后更新原楼层及当前 swipe，并保存到原聊天。服务端确认保存后显示成功；保存未获确认会提示状态，不自动重试。提交保存后不能再取消；提交前可取消 AI 请求。

AI 返回格式（配置页也可展开查看）：

```json
[
  { "at": "P001", "summary": "图片内容概括", "prompt": "该场景的生图提示词" }
]
```

`at` 必须是本次正文副本中提供的编号；`summary` 为单行概括；`prompt` 仅包含场景提示词。可返回多个对象，同一位置按数组顺序插入；空数组表示没有配图。接受纯 JSON 或完整的 JSON 代码围栏，拒绝额外解释和整篇改写正文。原有预设如返回完整正文，需要自行调整输出格式；插件不会改写导入预设。

标记使用以下四行结构（每个块均须闭合，提示词可占多行）：

```text
<img>
[图片内容概括]
该场景的生图提示词
</img>
```

每块在楼层中显示为独立生图按钮，围栏代码中的示例不解析。按钮只存在于显示层，聊天中保存的仍是原文与标记。点击时将“场景提示词, 画师工坊正面词”作为正面提示词，另行附上画师工坊负面词，并使用已保存的 NAI 连接及生图参数。AI 处理阶段不读取画师正负面词；没有自动生图。

场景概括、图片、排队状态和操作放在同一无边框区域，文字颜色跟随楼层。图片保持原比例，可点击放大、保存或重新绘制；重新绘制期间保留旧图，成功后原位替换。楼层重渲染或追加正文时保留同一标记的请求与预览，切换聊天或回复版本、删除标记或关闭解析时清理并取消相应排队项。图片预览仅保留在当前页面，未将图片另存进聊天附件。每条回复最多解析 64 个块；AI 处理支持原文最多 256 Ki 字符，返回内容及插入后正文最多 512 Ki 字符。插入块沿用原文换行风格，并在需要时补充分隔换行；原有空格和换行保持原样。

## 开发

```sh
npm install
npm run build
```

只有 TypeScript 编译依赖，没有额外运行时依赖。扩展使用酒馆提供的 jQuery 初始化和 `SillyTavern.getContext()` 保存偏好。

```text
manifest.json       酒馆扩展安装清单
src/index.ts        挂载、导航、窗口生命周期
src/launcher.ts     悬浮球拖动与边界处理
src/launcher-menu.ts 长按菜单与处理状态
src/pages.ts        页面定义及导航分组
src/views.ts        四个板块及系谱图
src/settings.ts     偏好结构与宿主存储
src/image-config.ts 生图配置交互与生成流程
src/image-view.ts   无边框配置页模板
src/image-settings.ts 浏览器本地配置存储
src/novelai.ts      NAI 模型、参数和请求
src/image-response.ts PNG / ZIP 响应读取
src/model-config.ts 模型配置交互与功能层选择
src/model-view.ts   模型连接与头尾预设界面
src/model-settings.ts 模型配置本地存储
src/model-types.ts  模型消息与连接类型
src/model-api.ts    模型列表和独立请求
src/model-service.ts 功能层调用的模型入口
src/preset-import.ts JSON 预设解析与结构保留
src/feature-layers.ts 功能注册与预设消息组装
src/chat-host.ts    酒馆楼层快照、冲突检查和保存
src/chat-processor.ts 处理最新回复与写回流程
src/image-markers.ts 闭合图片标记解析
src/image-insertion.ts 行间插入点、配图数据校验和本地拼接
src/image-text-regions.ts 文本行与代码、标签保护区
src/chat-images.ts  楼层生图按钮与画师词拼接
style.css           隔离在 Shadow DOM 内的样式
dist/               TypeScript 编译产物，随 Git 发布
```

新增功能时，在 `src/pages.ts` 登记页面，在 `src/views.ts` 添加页面内容与对应系谱图入口。

功能通过 `registerFeatureLayer({ id, title, messages })` 注册，返回的函数用于注销。注册后需由用户在功能层配置中启用；不会自动发送。`messages(context)` 接收本次输入消息、可选数据和取消信号，返回消息数组。`runConfiguredModel(context, onText?)` 使用已保存的模型配置，按“头部 → 已启用功能层（按启用顺序）→ 本次输入 → 尾部”组装并请求模型；`onText` 接收截至当前的完整正文。该入口不自动添加任何提示词，默认功能列表为空。

## Git 发布与安装

将**本目录内容**作为独立仓库的根目录，确保 `manifest.json` 位于仓库根。每次修改 TypeScript 后执行构建，并一同提交 `dist/` 和 `style.css`；用户安装时不需要编译。

仓库发布后，用户在酒馆“扩展 → 安装扩展”中填写该 Git 仓库地址，然后刷新页面，通过右下角“绘”悬浮球进入。

此目录不依赖角色卡工程、MVU 或酒馆助手。
