# 生图与出图 · 分支测试

测试分支：`codex/image-concurrency-auto-flow`。本次从 `main` 的 `8a72c9c` 开始，主分支不合并、不推送。

## 本次变化

- 「使用偏好」下新增「出图与生图」子页面：自动配图、并发与队列、图片留存。
- 原「自动 AI 生图」改名为「回复后自动写 Tag」，原「自动点击生图」改名为「新标记自动出图」。两个开关全开时，正文及后处理完成后自动写 Tag，再生成图片；保持原有预设及请求内容。
- 共享图片队列支持 1～4 张同时生成，默认 1。覆盖手动配图、自动配图、重绘、试绘与角色图；单张失败不自动重试。并发限制作用于当前页面。
- 自动出图按原文顺序启动，保留 0～60 秒等待与补位间隔；切换聊天或关闭功能取消相关自动任务，不补跑历史标记。
- 旧开关、间隔和留存值继续有效；完整配置导出、导入及恢复默认包含新并发字段。旧文件未提供并发数时用 1。
- 生图设置和使用偏好分别恢复默认。队列状态和悬浮入口显示正在生成的图片数。

## 已验证

2026-11-04～11-05：TypeScript 构建及 14 项无网络调度测试通过。覆盖 FIFO、乱序完成补位、动态调高/调低并发、取消、失败隔离、不补跑历史、聊天切换、宿主忙碌/画幅保存等待，以及正文后处理结束后写 Tag 再并发出图的串联。

实际浏览器载入 `dist/index.js`，使用本机模拟酒馆宿主，验证：

- 设置保存与两个自动开关的流程提示。
- 两页独立恢复默认。
- 真实配置导出、解析和文件选择导入；旧文件默认值、无效值拒绝，以及导入后运行中队列上限同步。
- 1280 × 900 桌面和 390 × 844 手机布局；手机正文无横向溢出，五个一级导航与使用偏好下的子页面入口可用；无页面运行异常。

运行调度测试：`npm test`（自动先构建）。浏览器测试需已有 Playwright，指定 `WITCH_PLAYWRIGHT` 为模块路径后运行 `node tests/workflow-browser.mjs`；截图默认放在 `/tmp/witch-image-workflow-preview/`。若本机 Node 环境开启了无效的环境代理，运行时设置 `NODE_USE_ENV_PROXY=0`。

范围：两个明确的模型 ID `gpt-image-2.6-flare` / `gpt-image-2.6-sunburst`，标准 Images API 的单张静态 PNG、新规划深度字段和尺寸检查。默认模型和已有模型参数保持，未改写任何模型预设或提示词。GIF、SVG、参考图与涂鸦编辑不在本次接入范围。

新增 8 项 `tests/openai-image-26.test.mjs`，使用原始生产模块、拦截的 fetch 和有效 PNG 字节，检查两个模型的标准请求、三个规划档位、默认省略、旧型号与未知别名隔离、尺寸拒绝与有效边界、旧配置兼容、队列参数冻结、错误不重试及模型列表发现。`npm test` 同时运行原 14 项队列测试与上述接口测试。

浏览器测试复用已有本机酒馆宿主，并以假密钥和拦截的模型列表／生图响应检查真实设置页、试绘、PNG 下载、IndexedDB 历史、图片属性、完整配置导入导出、旧历史默认值和手机布局。官方 API 域名在测试中主动阻断，不消耗模型额度。运行命令与前文相同；2.6 界面截图命名为 `gpt-image-26-desktop.png` / `gpt-image-26-mobile.png`。

参数依据：[图像生成指南](https://developers.openai.com/api/docs/guides/image-generation)、[Images API](https://developers.openai.com/api/reference/resources/images/methods/generate)、[2.6 模型设置说明](https://developers.openai.com/api/docs/guides/image-prompting)。尺寸沿用 GPT Image 系列的本地检查，真实服务可能有额外限制。未使用真实 2.6 API，尚未验证渠道是否开放模型或接收 complexity、实际延迟、图像质量、费用、服务限流和跨域配置。TT 存储复用既有配置机制，本次浏览器宿主未连接真实 TT。
